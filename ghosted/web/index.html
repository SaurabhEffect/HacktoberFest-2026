    How it works

    Three steps from silence to a reply you can send.

    1. 1

      Find the silent ones

      Ghosted lists a repository's open issues and keeps the ones with zero comments that have waited longest. Pull requests and anything that got a reply are skipped.

    2. 2

      Dig for the fix

      It searches merged pull requests, commits and release notes for each issue. “Fixes #12” is strong evidence. A lookalike title is only a hint, and it says so.

    3. 3

      Draft the reply

      A local model sorts each issue and writes the kind, specific answer the reporter should have received. You edit it, approve it and export a review sheet. Posting is your call.

    The three verdicts

    Every ghost gets one sticker.

    Already fixed

    Something merged after the report says it fixes it. The draft points at that evidence and asks the reporter to confirm.

    Still valid

    A clear report and nothing since addresses it. The draft apologizes for the silence, confirms what was understood and invites a maintainer in.

    Needs info

    Too thin to act on. The draft asks for exactly what is missing: the version, the steps, what was expected and what happened.

    Why local

    A sweep is thousands of calls. It should cost nothing.

    Ghosted runs on open weights, through Ollama or any OpenAI-compatible server on your machine. Once the model is on your disk, classifying a whole graveyard is free.

    1. 01It is thousands of calls.

      A big repository holds years of silent issues. At one model call each, a hosted API turns that into a bill. On your own machine it turns into electricity.

    2. 02Reporters are strangers.

      Issue text is untrusted input. Ghosted fences it off as data, and nothing a model writes can add a link, version or issue number that is not in the repository's own history.

    3. 03You can read all of it.

      Open weights, a Python app with zero dependencies and no telemetry. The only traffic is read-only requests to GitHub and to the model on your machine.

    Questions

    Before you point it at anything.

    Does Ghosted ever post to GitHub?

    No. It sends read-only GET requests to GitHub's API and has no code that writes. Drafts live in this page and in a local SQLite file. You copy the ones you want and post them yourself.

    Which model do I need?

    Any small instruction-tuned model. With Ollama, Gemma is listed first: ollama pull gemma3:4b is a fine start. LM Studio, llama.cpp's server and vLLM work through the OpenAI-compatible option. With no model at all, the rule-based preview runs the same evidence checks and fills in templates, so you can see the whole flow.

    How does it decide something is fixed?

    Only from evidence. A merged pull request or commit that says it fixes or closes the issue is strong evidence. A plain mention is weaker, and a similar title is only a hint that caps the confidence at low. If a model says “fixed” with nothing behind it, Ghosted downgrades the verdict to needs info.

    What about GitHub's rate limit?

    Without a token GitHub allows 60 requests an hour. A scan uses at most about 22 of them, so a few scans an hour are fine. A read-only token (typed in Settings, or set as GITHUB_TOKEN) raises that to 5,000. A token you type is kept in memory for that scan and never saved.

    Where does my data live?

    In a SQLite file at data/ghosted.db next to the app. Delete a scan under “Earlier hauntings” and its drafts are gone. There is no analytics, and even the fonts are bundled.
